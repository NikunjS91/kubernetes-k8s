Three-Tier Application — AWS EKS Deployment
============================================

Architecture
------------
- Frontend  : React          (Application Layer)
- Backend   : Node.js        (Logic Layer)
- Database  : MongoDB        (Data Layer)

Each layer runs in its own Docker container.
Images are pushed to AWS ECR → deployed on AWS EKS → routed via ALB Ingress.

Flow: Browser → ALB → Ingress → Service → Pod
      Frontend never talks directly to MongoDB; all DB access goes through the backend.


Step 1 — EC2 Setup & Docker Build
----------------------------------
1. Launch EC2, SSH into it.
2. Pull source code from GitHub.
3. Install Docker on EC2.
4. Add user to docker group:
      sudo usermod -aG docker $USER
      sudo chmod 666 /var/run/docker.sock
5. Write Dockerfile for each service:
      base image → COPY package*.json → RUN npm install → COPY source code
6. Build images:
      docker build -t <image-name> .
7. Open required ports in EC2 Security Group.
8. Test locally, then kill container:
      docker kill <container-id>


Step 2 — Push Docker Images to AWS ECR
----------------------------------------
1. Install AWS CLI on EC2.
2. Create IAM user with AdministratorAccess → generate access keys.
3. Configure CLI:
      aws configure
4. Create one ECR repository per service (frontend, backend).
5. Authenticate Docker with ECR:
      aws ecr get-login-password --region <region> | \
        docker login --username AWS --password-stdin <account-id>.dkr.ecr.<region>.amazonaws.com
6. Tag and push images:
      docker tag <image>:latest <ecr-uri>/<repo>:latest
      docker push <ecr-uri>/<repo>:latest


Step 3 — Kubernetes Cluster Setup (EKS)
-----------------------------------------
1. Install kubectl.
2. Install eksctl.
3. Create EKS cluster:
      eksctl create cluster --name <cluster-name> --region <region> --nodes 2
4. Bind kubectl to the EKS cluster (set context):
      aws eks update-kubeconfig --region <region> --name <cluster-name>
5. Verify:
      kubectl get nodes


Step 4 — Deploy Kubernetes Manifests
--------------------------------------
Deploy in this order:
  1. Secret          — MongoDB credentials (base64 encoded)
  2. MongoDB         — Deployment + ClusterIP Service
  3. Backend         — Deployment + ClusterIP Service
  4. Frontend        — Deployment + ClusterIP Service
  5. Ingress         — Path-based routing (/frontend, /backend)

Commands:
  kubectl create namespace three-tier
  kubectl apply -f secret.yml
  kubectl apply -f mongodb-deployment.yml
  kubectl apply -f backend-deployment.yml
  kubectl apply -f frontend-deployment.yml
  kubectl apply -f ingress.yml
  kubectl get all -n three-tier


Step 5 — ALB Ingress Controller (Helm)
----------------------------------------
1. Install Helm.
2. Download IAM policy for the AWS Load Balancer Controller:
      curl -O https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/main/docs/install/iam_policy.json
      aws iam create-policy --policy-name AWSLoadBalancerControllerIAMPolicy \
        --policy-document file://iam_policy.json
3. Associate OIDC provider with EKS:
      eksctl utils associate-iam-oidc-provider --cluster <cluster-name> --approve
4. Create IAM service account and attach policy:
      eksctl create iamserviceaccount \
        --cluster <cluster-name> \
        --namespace kube-system \
        --name aws-load-balancer-controller \
        --attach-policy-arn arn:aws:iam::<account-id>:policy/AWSLoadBalancerControllerIAMPolicy \
        --approve
5. Install controller via Helm:
      helm repo add eks https://aws.github.io/eks-charts && helm repo update
      helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
        -n kube-system \
        --set clusterName=<cluster-name> \
        --set serviceAccount.create=false \
        --set serviceAccount.name=aws-load-balancer-controller
6. Apply Ingress manifest with ALB annotations → done.
