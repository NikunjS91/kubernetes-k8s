here we have been running pods because we want to have self-healing and scalable systems,
well to achieve that we use deployment strategies.

not user interact with a container with an app or service, in case of deletion of pod my tend to lose the data so we need storage to make it persistant.
so we persist the data with host.
so we need pc and pvc persistant volumene and persistant volume claim

lets make a persistant volume
vim persistantVolume.yml

kind: PersistentVolume 
apiVersion: v1 
metadata:
    name: local-pv 
    namespace: nginx            ##error below we talked
    labels:
        app: local
spec:
    capacity:
        storage: 1Gi 
    accessModes:
        - ReadWriteOnce
    persistentVolumeReclaimPolicy: Retain 
    storageClassName: local-storage 
    hostPath:
        path: /mnt/data

kubectl apply -f persistantVolume.yml
kubectl get pv

now the volume is created need to claim.

to do that:
    vim persistantvolumeclaim.yml

kind: PersistentVolumeClaim 
apiVersion: v1 
metadata:
    name: local-pvc
    namespace: nginx            ##error below we talked
spec:
    accessModes:
        - ReadWriteOnce 
    resources:
        requests:
            storage: 1Gi
    storageClassName: local-storage

kubectl apply -f persistantvolumeclaim.yml

check with this not it wont be avaible rather it will be bound as status with below command:
    kubectl get pv

to check more details about bound with deatils do:
    kubectl get pvc

now we will give the claim to the pod

with this we have pv and pvc, pv means from host we got 1gb on space with the path,
pvc means we have clamed it and its in bound.

not we have to make changes in our deployment featuring volume mounting from container volume to local host storage which is our pv and pvc.
with configs
changes done:
volumeMounts:
- mountPath: /var/www/html 
  name: my-volume
volumes:
- name: my-volume 
  persistentVolumeClaim: 
    claimName: local-pvc

now that the pods are running how do we see them?

the pod has deployment to make it accessable for external user, which can be done via service proxy.
need to create service resource with this it helps to redirect to multiple deployment.

lets create one service:
    vim service.yml

kind: service
apiversion : v1
metadata:
    name: nginx-service
    namespace: nginx
spec:
    selector:
        app:nginx
    ports:
        -protocol:TCP
        port:80
            targetPort:80
    type: ClusterIP

kubectl apply -f service.yml

to see all pods , deployment and service in one command:
    kubectl getall -n nginx

not we have to access the service on our browser which was our question before.
befor that we need to expose our docker containers ip and port forwarding with can be done with this commands:
    kubectl port-forward service/nginx-service -n nginx 80:80 --address=0.0.0.0

    after running this command over ec2 it may show an error that persmission required which wont be the case in local system.
    we can bypass that with the sudo -E this gives is a environmant

    command:
        sudo -E kubectl port-forward service/nginx-service -n nginx 80:80 --address=0.0.0.0 
    this will run if not then check for another port maybe that port is already in use

    after that on aws open port 80 in ec2 security group for traffic inbound and we are good to go, put in the url ip address of the ec2 machine and the port number with : and you may see out nginx welcome page ther.
